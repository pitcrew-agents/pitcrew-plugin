# Agent JSON Schema Reference

This is the authoritative specification for a valid agent draft.
The edit_worker builds agents by calling the granular tools (init_board, add_swimlane, add_task, etc.)
which internally construct this structure. Read this to understand what each field means
and what constraints apply.

---

## Top-level Agent Object

```json
{
  "name":          "Human-readable agent name",
  "description":   "One paragraph: what this agent does",
  "instructions":  "Optional guidance shown to the user when running the agent",
  "input_schema":  { ... },
  "swimlanes":     [ ... ],
  "default_model": null,
  "intent":        { "statement": "...", "success_criteria": "...", "approach": "..." },
  "knowledge":     { "good_examples": [...], "careful_zones": [...], "known_limitations": [...] },
  "configurations": null
}
```

| Field | Required | Notes |
|---|---|---|
| `name` | Yes | Short, descriptive |
| `description` | Yes | Plain English, 1–3 sentences |
| `input_schema` | Yes | JSON Schema (see below). Can have empty properties. |
| `swimlanes` | Yes | At least one |
| `instructions` | No | Shown in run UI |
| `default_model` | No | Leave null — runtime default applies |
| `intent` | No | Populated by plan_worker |
| `knowledge` | No | Populated post-build |
| `configurations` | No | Auto-generated by config builder |

## input_schema

Defines what the user fills in each time they run the agent (per-run inputs).
Do NOT include one-time settings here — those go into `configurations`.

```json
{
  "type": "object",
  "properties": {
    "document_url": {
      "type": "string",
      "format": "file",
      "displayName": "Document to Analyse",
      "description": "Upload the PDF or Word document"
    },
    "advisor_email": {
      "type": "string",
      "displayName": "Advisor Email",
      "description": "Email address to send the report to"
    }
  },
  "required": ["document_url"]
}
```

### Property formats

| `type` + `format` | What it renders in UI | Path prefix |
|---|---|---|
| `"string"` (no format) | Text input | `$.run_input.field_name` |
| `"string"`, `"format": "file"` | File upload button | `$.files.field_name` |
| `"string"`, `"format": "url"` | URL input | `$.run_input.field_name` |
| `"number"` | Number input | `$.run_input.field_name` |
| `"boolean"` | Toggle | `$.run_input.field_name` |

**Rules:**
- Every property in `input_schema.properties` creates one user-visible input field.
- Fields with `"format": "file"` are accessed as `$.files.field_name` in task mappings.
- All other fields are accessed as `$.run_input.field_name`.
- A field referenced as `$.run_input.X` or `$.files.X` in any task mapping MUST exist in `input_schema`.

## Swimlane Object

```json
{
  "name":         "Swimlane Name",
  "position":     0,
  "instructions": "Optional: what this phase of the workflow does",
  "tasks":        [ ... ],
  "exit_criteria": null,
  "branch_group": null
}
```

| Field | Notes |
|---|---|
| `name` | Unique within the agent. Shown in the UI. |
| `position` | 0-indexed. Auto-managed by tools — don't set manually. |
| `instructions` | Optional description shown to users. |
| `tasks` | At least one task required. |
| `exit_criteria` | null (default) or a conditional routing object (see below). |
| `branch_group` | null (default) or a string grouping branch swimlanes together. |

**Swimlanes execute sequentially from position 0 to N.**
The last swimlane always produces the final output.

## Task Object

```json
{
  "name":           "Task Name",
  "instructions":   "What this task does — required for every task",
  "task_type":      "llm_call",
  "position":       0,
  "input_mapping":  { "param_name": "$.run_input.field" },
  "output_mapping": { "raw_response": "$.state.result" },
  "output_schema":  null,
  "tool_config":    null,
  "dependencies":   [],
  "model_override": null
}
```

### task_type values

| `task_type` | What it does |
|---|---|
| `"llm_call"` | Sends instructions + mapped inputs to Claude. Response written via output_mapping. |
| `"tool_call"` | Calls an external tool (integration, file reader, report generator, etc.). |

### tool_config — CRITICAL: tool_name naming rule

The `tool_name` in `tool_config` MUST be exactly the `## heading` name from the tool's markdown file.
**Never** prefix it with the filename, category, or directory path.

```
✅ CORRECT                       ❌ WRONG — will cause "tool not found" at runtime
"tool_name": "add"               "tool_name": "math_tools.add"
"tool_name": "read_pdf"          "tool_name": "pdf_tools.read_pdf"
"tool_name": "analyze_csv"       "tool_name": "csv_analysis_tools.analyze_csv"
"tool_name": "generate_report"   "tool_name": "report_tools.generate_report"
"tool_name": "GMAIL_SEND_EMAIL"  "tool_name": "gmail.GMAIL_SEND_EMAIL"
```

When you read a tool file and see `## add` under `# math_tools`, the tool_name is `"add"`.
The `# math_tools` heading is just the file/category label — it is NOT part of the tool_name.

### instructions field

- **llm_call**: The prompt sent to Claude. Reference input fields by name — they will be injected.
- **tool_call**: Human-readable description of what the tool does. Not sent to Claude.

### dependencies

Array of integer task **positions** within the same swimlane that this task depends on.
The first task in every swimlane must have `dependencies: []`.
Tasks in different swimlanes are automatically sequential — no cross-swimlane dependencies needed.

```json
// Task at position 2 depends on task at position 1
{ "name": "Validate Result", "position": 2, "dependencies": [1] }
```

## output_mapping

Specifies where the task's output is written in the shared run state.

### For llm_call tasks

```json
// Free-text LLM response (no output_schema needed)
{ "raw_response": "$.state.summary_text" }

// Structured output (requires output_schema)
{ "parsed": "$.state.compliance_result" }
```

Use `"parsed"` + `output_schema` when downstream tasks need specific fields from the LLM response.
Use `"raw_response"` when the output is a plain string (email draft, summary, etc.).

### For tool_call tasks

Each tool documents its own output keys. Common examples:

```json
// read_pdf
{ "content": "$.state.document_text" }

// analyze_csv
{ "analysis": "$.state.csv_analysis" }

// generate_report (FINAL TASK — always write to $.state.final_report)
{
  "json_report":    "$.state.final_report",
  "content_type":   "$.state.report_content_type"
}
```

**CRITICAL: The last task in the last swimlane MUST write to `$.state.final_report`.**
Use `generate_report` tool for rich structured output (tables, stats, badges).
Use `{ "raw_response": "$.state.final_report" }` only for simple text output.

## output_schema

Used only on `llm_call` tasks when structured output is needed.
The schema MUST be flat — no nested `"type": "object"` properties.

```json
{
  "type": "object",
  "properties": {
    "compliance_status":  { "type": "string",  "description": "PASS, FAIL, or REVIEW" },
    "violation_count":    { "type": "integer", "description": "Number of violations found" },
    "summary":            { "type": "string",  "description": "One-sentence summary" }
  },
  "required": ["compliance_status", "violation_count"]
}
```

**Rules:**
- Must be flat — no property may have `"type": "object"`.
- Use underscore naming for multi-word concepts: `risk_level` not `risk.level`.
- If you need sub-fields, flatten them: `policy_name`, `policy_id` instead of `policy: {name, id}`.

## Conditional Routing (exit_criteria)

When a swimlane needs to branch to different downstream swimlanes based on a result:

```json
{
  "exit_criteria": {
    "type": "conditional_routing",
    "description": "Route by compliance status",
    "branches": [
      {
        "label": "High Risk",
        "eval_mode": "structured",
        "condition": "$.state.risk_score > 80",
        "target_swimlane_position": 2
      },
      {
        "label": "Medium Risk",
        "eval_mode": "structured",
        "condition": "$.state.risk_score > 40",
        "target_swimlane_position": 3
      }
    ],
    "default_branch": {
      "label": "Low Risk",
      "target_swimlane_position": 4
    }
  }
}
```

Branch swimlanes that reconverge must share a `branch_group` string and have `next_position` in their exit_criteria:

```json
// Branch swimlane A (position 2)
{
  "branch_group": "risk_path",
  "exit_criteria": { "next_position": 5 }
}

// Branch swimlane B (position 3)
{
  "branch_group": "risk_path",
  "exit_criteria": { "next_position": 5 }
}

// Reconvergence swimlane (position 5) — no branch_group
```

**eval_mode values:**
- `"structured"` — condition is a JSONPath expression evaluated against run state.
- `"llm_judge"` — condition is a natural-language question sent to an LLM.

## Typical Agent Structure

```
Swimlane 0: Data Ingestion
  Task 0: Download/read uploaded file    [tool_call: read_pdf / analyze_csv]
  → writes $.state.document_text

Swimlane 1: Processing
  Task 0: Extract structured data        [llm_call with output_schema]
  → writes $.state.parsed_data (via "parsed" output_mapping)
  Task 1: Call validation tool           [tool_call]
  → depends on [0], writes $.state.validation_result

Swimlane 2: Report Generation  ← LAST SWIMLANE
  Task 0: Generate report                [tool_call: generate_report]
  → input_mapping reads $.state.* fields
  → output_mapping: {"json_report": "$.state.final_report",
                     "content_type": "$.state.report_content_type"}
```

## Complete Minimal Example

```json
{
  "name": "PDF Compliance Checker",
  "description": "Reads an uploaded PDF, checks it against compliance rules, and generates a report.",
  "input_schema": {
    "type": "object",
    "properties": {
      "document": {
        "type": "string",
        "format": "file",
        "displayName": "Document to Check",
        "description": "Upload the PDF document"
      }
    },
    "required": ["document"]
  },
  "swimlanes": [
    {
      "name": "Extract Content",
      "position": 0,
      "tasks": [
        {
          "name": "Read PDF",
          "task_type": "tool_call",
          "position": 0,
          "instructions": "Extract text content from the uploaded PDF.",
          "tool_config": { "tool_name": "read_pdf", "params": {} },
          "input_mapping": { "document_url": "$.files.document" },
          "output_mapping": { "content": "$.state.document_text" },
          "dependencies": []
        }
      ]
    },
    {
      "name": "Check Compliance",
      "position": 1,
      "tasks": [
        {
          "name": "Analyse for Violations",
          "task_type": "llm_call",
          "position": 0,
          "instructions": "Review the document text for compliance violations. Identify each issue found.",
          "input_mapping": { "document_text": "$.state.document_text" },
          "output_mapping": { "parsed": "$.state.analysis" },
          "output_schema": {
            "type": "object",
            "properties": {
              "violation_count": { "type": "integer", "description": "Number of violations" },
              "status":           { "type": "string",  "description": "PASS or FAIL" },
              "findings":         { "type": "string",  "description": "Summary of findings" }
            },
            "required": ["violation_count", "status"]
          },
          "dependencies": []
        }
      ]
    },
    {
      "name": "Generate Report",
      "position": 2,
      "tasks": [
        {
          "name": "Build Compliance Report",
          "task_type": "tool_call",
          "position": 0,
          "instructions": "Generate a structured compliance report.",
          "tool_config": { "tool_name": "generate_report", "params": {} },
          "input_mapping": {
            "title":        "Compliance Check Report",
            "instructions": "SECTION 1: stat:row with violation_count and status. SECTION 2 (title: Findings): text with findings.",
            "inputs": {
              "violation_count": "$.state.analysis.violation_count",
              "status":          "$.state.analysis.status",
              "findings":        "$.state.analysis.findings"
            }
          },
          "output_mapping": {
            "json_report":  "$.state.final_report",
            "content_type": "$.state.report_content_type"
          },
          "dependencies": []
        }
      ]
    }
  ]
}
```
